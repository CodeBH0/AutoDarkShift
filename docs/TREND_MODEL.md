# 亮度数学模型 v2 与动态采样

生产模型由 [数学模型 v2](models/MathModel-v2.md) 定义；[v1](models/MathModel-v1.md) 原文保留。屏幕亮度不是环境照度；本轮参数来自实测逻辑问题和数学不变量，未由带外观标签数据拟合。

1.0.3 的类型化亮度消息业务复用本模型，不启动轮询；模型的频率建议不代表实际采样频率。首次样本基线、超过两秒的观测间断重置、通知冷却和去重继续使用；消息稀疏时可能仅重新建立基线，冷却后的重试需有新消息。该源码尚未编译或真机验证，详见 [BRIGHTNESS_MESSAGE.md](BRIGHTNESS_MESSAGE.md)。

## 分量与评分

原始 B 经过 0.005 幅度滞回得到接受值 b。比较上一接受值，持续微小单向步进仍能累积；首次静止读数 S=0。

| 分量 | v2 实现 |
| --- | --- |
| A | clip((b−0.25)/0.15,−1,1)，作为位置坐标 |
| A_aligned | AΔ>0 时取 A，其余为 0，只支持确认方向 |
| Δ | sign(d)×clip((\|d\|−0.005)/(0.15−0.005),0,1)，d=b−B₀，无起点为 0 |
| v | 所有档位/来源共用完整 1 秒插值速度窗，不足一秒为 0 |
| V | 同向 0.5 秒预测位移除以 0.15，上限为已发生位移及剩余亮度空间 |
| S | 0.25A_aligned+0.55Δ+0.20V |

**D 已删除**，不维护有效方向次数/窗口。v 调频，V 是预测位移。S≥0.50 产生 light，S≤−0.50 产生 dark，其余保持此前目标并清除 pending。累计权重 0.55 使明显净变化在减速/静止后仍可等冷却重试。

成功历史只说明系统接受通知，不能确认快捷指令或实际外观。inFlight 保留原目标、原始亮度和来源，评分回落不取消普通在途流程；同一时刻仅一项请求。生命周期变化可取消尚未提交的旧请求，已调用通知中心的请求仍记录结果。success / failed / blocked 推进既有冷却；cancelled 不推进或清除冷却，不更新历史。

## 基线、时间与采样

首接受值为 anchor；偏离超过 0.005 建立 B₀，维护峰或谷。恢复 1 Hz、速度归零、长期静止或通知都不重设 B₀。低于 Boost 门槛的同向慢变化沿同一 B₀ 累计，不采用每 2 秒自动稳定锚。

相对本轮峰/谷的累计反向达到 **0.010** 时从该极值重建 B₀；微小反向抖动不重置。明确反向或观测重置结束旧轮次；静止后继续同向仍保留旧累计证据，是本轮明确边界。

常规 1 Hz，速度绝对值至少 0.015/s 进入 Boost。Boost 内分别用 10（不足0.03）、30（至少0.03）、60（至少0.06）、120（至少0.10）Hz；连续实际观测低于0.01/s达0.30秒退出。进入、退出、调频均不清速度窗/B₀，台阶速度不再因进入时清窗在下一读数归零。

速度、插值、去重和退出计时用单调时间，同刻事件/轮询只接受先到者；墙钟用于日志与冷却。非法读数、时间倒退、睡眠/唤醒/停止/配置更新重置。运行时超过 `max(2 秒, 当前轮询间隔×2)` 的采样间断显式重置。

相同亮度轨迹无法区分手动调节和真实环境；静止高亮/低亮不自动请求外观。

## 记录、回放与迁移

运行日志与 Boost 记录独立写入/导出，格式见 [BOOST_TRACE_LOG.md](BOOST_TRACE_LOG.md)。capture 的“2 秒内波动≤0.005”只决定记录完成，不参与基线与评分。

`tools/replay_trend.py` 支持清洗 CSV 和原始/解码 JSONL，按实例+sequence去重，直接编译生产 Swift 模型。首窗口冷启动与缺口重置显式报告；新 v2 记录状态评分核验与轨迹回放分开。报告、原始输入留在忽略的 `local-data/`。

196 条 Boost 行对应 105 个独立观测；同一记录网格回放，频率变更26→21次，连续段内B₀变更8→0次。输入前史缺失、无外观标签，不能解释为真机正确率/真实反应时提升。证据、公式、校验值与限制见 v2 文档。

新运行快照 schemaVersion=3。旧快照可读，但旧 speed 使用 v1 含义，界面按版本区分。新 `filteredBrightness` 和 `projectedBrightness` 记录接受值/预测位置；旧快照可缺省。配置只保留 revision 和冷却，旧阈值/固定轮询/实验参数不参与。

主 App/扩展共享版本与build，每次打包递增，通信继续校验身份。实际验证范围见 [STATIC_VALIDATION.md](STATIC_VALIDATION.md)，真机行为按 [DEVICE_ACCEPTANCE.md](DEVICE_ACCEPTANCE.md) 记录。
