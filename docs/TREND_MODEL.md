# 1.0.1 亮度趋势评分与动态采样

本次只依据 `MathModel v1.md` 的第 1–4 章和第 8 章。未实现第 7 章的参数自优化，也不使用第 5–6 章作为验算或验收依据。固定权重和初始参数用于正式监听，既有 VPN、通知权限、冷却、成功历史去重与日志通信继续使用。

## 评分

| 分量 | 实现 |
| --- | --- |
| A | clip((B − 0.25) / 0.15, −1, 1) |
| Δ | clip((B − B₀) / 0.15, −1, 1) |
| V | clip(v / 0.10, −1, 1) |
| D | 最近 N 次有效变化的 (N₊ − N₋) / N |
| S | 0.25A + 0.35Δ + 0.30V + 0.10D |

S ≥ 0.50 产生 light 候选，S ≤ −0.50 产生 dark 候选；其余保持此前目标并清除尚未进入 inFlight 的待处理目标。不存在旧版稳定时间门槛。同一成功请求去重；失败、权限不足及冷却后的重试都需要新的评分合格样本。成功历史仅说明系统接受过通知，不说明系统外观或外部快捷指令的实际结果。

候选进入 inFlight 后，固定其目标、亮度和来源，继续完成授权与提交；后续评分回落、pendingTarget 改变或观测窗口重置都不撤销该请求。同一时间只允许一个 inFlight，请求结束后再由新样本评估下一候选。停止、睡眠 / 唤醒和配置重载改变生命周期代次，可在授权返回时取消尚未提交通知中心的旧请求；已经调用通知中心 add 的请求仍完成结果记录。

候选生成不推进冷却时间。success / failed / blocked 终态沿用原有规则，以完成时刻更新冷却；尚未实际提交的 cancelled 仅释放 inFlight，不推进或清除此前冷却，不更新成功历史、实际提交次数或成功次数。重复和迟到回调不能再次调用 add 或重复记录成功。

文档未给定 N，当前取 **10**，启动不足 10 次时用已有有效变化数作分母；空窗口 D = 0。严格按相邻读数判断有效变化，绝对变化小于 0.005 不计入方向；噪声读数仍参与速度估计。首次读数没有累计变化、速度和方向证据，仅计算 A，不能单凭静止亮度达到 ±0.50。

明显变化以常规速度 |v| ≥ 0.015 / 秒为起点，B₀ 取触发前的有效读数。在一轮动态采样期间保留 B₀，方向统计始于该变化，反向变化也进入最近 N 次统计。退出动态采样只清除速度窗口和方向记录，恢复 1 Hz 后继续保留 B₀，使 Δ 在减速与稳定阶段仍有效。检测到下一次明显变化时，以新变化前的稳定读数重新建立起点；睡眠、唤醒、停止、配置更新、非法输入和长采样间断等明确的观测重置仍清除 B₀。

## 速度和采样

常规为 1 Hz，使用相邻轮询读数及实际时间间隔估计速度，initial / wake 建立首个基准。常规期间的事件读取更新亮度位置，尚无轮询速度证据时 V = 0；事件不替换常规速度参照，避免毫秒级事件间隔放大速度并误触发。动态期间的事件和轮询均更新全部评分与固定时间窗。不把事件计数当作轮询计数。动态期间使用约 0.20 秒固定时间窗，在 `t − 0.20 秒` 处用相邻观测插值，适应频率变化和不均匀调度。进入动态后的窗口尚未积满时，暂用动态起始读数到当前的实际时间；不把先前 1 秒样本间隔当作高速窗口。速度和退出时长都使用系统单调时间，重复时间戳不参与差分。

| 动态速度绝对值（每秒） | 目标频率 |
| --- | --- |
| 0.015 ≤ |v| < 0.03 | 10 Hz |
| 0.03 ≤ |v| < 0.06 | 30 Hz |
| 0.06 ≤ |v| < 0.10 | 60 Hz |
| |v| ≥ 0.10 | 120 Hz |

每个有效新样本重新计算全部评分并选择频率。模型没有规定进入动态后 |v| < 0.015 时的档位，当前保持最低动态档 10 Hz，直到连续 |v| < 0.01 达 0.30 秒后退出，恢复 1 Hz。若任一新样本不满足低速条件，则重新开始低速计时。退出由实际观测的时长决定，不能用固定样本个数代替。

正式算法只产生上述五个档位。240 / 500 / 1000 Hz 实验能力保留于此前归档，本次不重新接入运行代码。调频只替换轮询定时器，保留亮度事件观察者和有效候选。高速常规快照与评分日志按秒节流，档位变化、候选变化和通知结果单独记录；真实计数仍包含每个读数。

## 模型边界和迁移

输入是系统屏幕亮度 B(t)，不是环境照度。模型表达相对上一稳定状态明显变亮 / 变暗的证据；相同 B(t) 轨迹无法严格区分环境。手动亮度与自动亮度产生相同轨迹时，算法也会给出相同结果。首次静止高亮度或低亮度不自动发出模式请求。

升级读取旧配置时只保留 revision 和通知冷却时间；旧亮度阈值、固定轮询间隔、稳定时间、Boost 参数不影响模型，后续保存移除旧字段。快照 schemaVersion = 2，新增 trend；旧快照可读取，新实例仅恢复计数与成功请求历史，不恢复旧趋势或测试档位。主 App 和 Packet Tunnel 共用 `Config/Project.xcconfig` 中的版本和 build 号，当前打包为 1.0.1 / build 11。每次打包自动递增 build；通信协议仍为 3，build 身份校验阻止旧扩展误配。
