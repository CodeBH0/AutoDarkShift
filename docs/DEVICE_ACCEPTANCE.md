## 可选诊断

消息回复、事件计数、精确间隔、心跳、sleep/wake、完整后台日志覆盖分别记录为可读取或不可观测。只有轮询样本时，不把轮询冒充 event；有界日志尾部不能代表整个测试时段。没有回复不等于扩展已停止，也不能证明该通信能力永久不可用。

版本不兼容、坏回复、非法参数、运行存储失败和扩展明确拒绝仍需处理。若功能正常而详情不可读取，保留这个结论即可，无需为取得全部诊断字段反复重装。

## 趋势评分与动态采样专项

1. 对照 [数学模型 v2](models/MathModel-v2.md) 与 `trend_score`：D 已删除，`S = 0.25A_aligned + 0.55Δ + 0.20V`。V 是受实际变化约束的预测贡献，绝对亮度 A 与 Δ 相反时不参与评分。目标仍由评分 ±0.50 判断。
2. 查看 `sampling_rate_changed`、`activePollInterval` 与 `lastPollInterval`：常规 1 Hz；动态一秒窗口速度绝对值在 0.015 / 0.03 / 0.06 / 0.10 档位边界对应 10 / 30 / 60 / 120 Hz。初始窗口不足一秒时不能靠事件间隔外推速度。
3. 连续以 0.05 左右的台阶降低亮度，台阶之间暂停不到 2 秒，检查累计 Δ 沿同一基线保留，降频不会丢失变化起点；随后保持稳定，合格通知可在冷却到期后重试。速度连续低于 0.01 / 秒至少 0.30 秒时恢复 1 Hz，实际退出时刻受观测与调度影响。
4. 验证睡眠、唤醒、异常采样和长间断后重新建立基准；不把缺失采样期间的变化计为连续趋势。
5. 在高亮区明显降低亮度，检查不会由相反方向的 A 产生浅色请求；低亮区升高同样检查。围绕峰 / 谷小幅抖动低于 0.010 时不应重置基线，超过该累计反向幅度才建立反向起点。
6. 缓慢单向变化低于 Boost 入口速度时，累计 Δ 仍应保留；静止首次读数与小于 0.005 的变化不能单独切换。
7. 高频仍统计每次事件 / 轮询，常规样本和评分日志被节流；依据计数差和实际采样时间评估达成率。正式代码最高 120 Hz，旧实验扫描已移出项目。

1. 仪表、保活、信息使用系统底部 Tab Bar；各页独立导航。仪表当前状态显示监听轮询频率、S、采样亮度和当前 App 可见外观；切换监听与通知统计二级功能可返回并持续刷新。不要把通知目标当作真实外观。
2. 不开 VPN，单独开启 PiP：来源区域可见时确认系统浮窗真正出现；退到桌面至少 30 分钟，在各时间点形成新的合格亮度趋势。返回核对 App 内监听来源与两路导出。系统关闭浮窗后开关应回到关闭。记录系统画中画设置及与其他媒体的冲突 / 中断。

5. 由 App 开关 VPN，检查 App→扩展及扩展→App 的交接；在通知刚提交时也交接，核对已获取的成功历史、冷却与去重，无多实例重复通知。再从系统设置断开 VPN，分别记录历史是否取得与功能恢复。
